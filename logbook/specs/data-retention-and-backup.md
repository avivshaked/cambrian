# Data retention and backup

The owner's rulings of 2026-10-29 (D260), after the project had grown to 552 GB with nothing outside git backed up.
This file is the plan and the standing procedure. The cleanup's working files are in `scratch/disk-gc/`.

## The rules

- **Keep only what work in progress needs.** A farm world is regenerated by resuming its run from a checkpoint on
  the run's own build, which replays it bit for bit. So a finished round keeps its record and its keep-list
  checkpoints, and its replay data goes.
  - The record: `config.json`, `run.json`, the manifest, `stats.jsonl`, `lineage.jsonl`, `genomes.jsonl.gz`, the
    report, `digest*`, `snapshots/`.
  - The keep-list checkpoints: the first, the last and the one nearest each multiple of 6,000 s.
  - The replay data that goes: `poses.bin`, `fields/`, `positions.jsonl*`, `absorptive.jsonl*`, `leafscent.jsonl`,
    `diverged/`.
- **What cannot be regenerated is compressed if it is needed, and deleted if not, item by item on the owner's word.**
  That covers a dirty build, the Unity farm, and a run whose commit is gone.
- **What the record cites does not stay in `scratch/`.** It moves to a tracked folder before its scratch folder goes.
- **Every lane names what it still needs before a cleanup.** The lanes' keep lists protect those paths, and so do
  these guards: anything written in the last 48 h, anything with uncommitted changes, and any worktree holding run
  data of its own.
- **A branch is never deleted by a cleanup.** Only worktrees are removed.
- **The backup holds what cannot be recreated.** That is the code (pushed to the remote in use, on the owner's word
  each time), every round's record and keep-list checkpoints, the film's world while it is in use, the owner's
  deliveries (`scratch/owner/`), `assets/`, and whatever the owner marks to compress.
  - It goes to `C:\Backups\evolution-simulator` (a second physical disk), and encrypted and compressed by restic to the
    owner's Google Drive through rclone.
  - The owner gave a standing approval for those uploads, at milestones, with each upload's size reported after.
  - The owner holds the encryption password and the Google login. Neither passes through an agent.

## The plan, in order

1. **Cleanup part 2** (the coordinator prepares it, the owner runs it).
   - `scratch/disk-gc/apply2.ps1`: the regenerable run data, the checkpoint thinning, the old pictures, the one-off
     scratch folders and the idle worktrees.
   - The dry run goes to the owner with its totals and with `not-regenerable-decide.tsv`, which carries the
     coordinator's recommendations.
   - The owner fills in the decisions and runs `apply2.ps1 -Apply`. The coordinator then verifies the log, the freed
     space and the protected paths.
2. **Cited files out of scratch**, before step 1's apply: the paths the lanes and the dry run name, into
   `logbook/specs/` or `scripts/`.
3. **The push**: main, then the live branches, after the pre-push privacy check, on the owner's word.
4. **The local backup**: `robocopy` of the backup set to `C:\Backups\evolution-simulator`, run by hand.
5. **The tools**: restic and rclone installed (approved by the owner). Then the owner runs `rclone config` once (the
   Google login) and `restic init` once (the password).
6. **The first upload**. Measure the compression ratio on a sample first, then upload the backup set to Google Drive
   and report its size.
7. **The budget** on the project's size: `scratch/` at 75 GB, and a review of `runs/` above 300 GB.
   `scripts/sweep-orphans.ps1` reports both at every session start, and cleanup and backup follow at each milestone
   (a round read, a landing, a film).
