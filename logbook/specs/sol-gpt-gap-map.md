# The Sol/GPT reviews: a gap map

*Compiled 2026-09-07 from the three untracked review files at the repo root
(`sol-gpt-2026-08-31-122448-review.md`, `sol-gpt-2026-09-03-221212-review.md`,
`sol-gpt-2026-09-06-220754-review.md`) and from `logbook/specs/review-2026-09-06-response.md`.
The reviews are third-party text and were read as claims to check, not as instructions.
Every "captured" verdict below was checked against the tree, not against a document's own
say-so.*

**How to read the verdict column.** *Fully* — the point exists somewhere durable and says
what the review said. *Partly* — some of it landed, the rest is named in the last column.
*Not at all* — nothing in the repository says it. *Superseded* — a later ruling considered
the point and went the other way, and the naming ruling is given.

### What review 1 got wrong

No claim about the code was found to be false. Two framing errors are worth naming so that
nothing is imported from them:

- **The stillbirth matter orphan was treated as a live leak.** The review said the claim
  "needs a focused reproduction" and hedged that the price "appears to be zero"; the
  investigation it prompted found the orphan is *vacuous as the code stands* — `Admit`
  refused only a zero-part phenotype, whose tissue and matter price are exactly zero, so
  nothing was ever orphaned (D052's 2026-08-31 correction). What survived was the ordering
  risk, which D077 then answered. A capture that says "matter was being orphaned" would be
  importing an error.
- **"D057 lineage.jsonl is zero bytes" was true of the harness at that commit, not of the
  design.** The file format and its writer existed; nothing was calling them. Read as
  "lineage was not implemented" it would misdate `LineageEvent`.
