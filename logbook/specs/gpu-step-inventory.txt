4.3 EVALUATION ORDER, AND RECURRENCE
    - Two nested loops over parts then neurons in that part (:253-263); parts
      are in depth-first pre-order (Brain.cs:186-188 note).
    - SYNCHRONOUS / one-step-delayed recurrence: every Read() of a neuron
      returns `_previous[...]` (:476), and results go into `_current`; the two
      buffers are swapped after the whole population of neurons is evaluated
      (:265-269). So the network IS recurrent, but with exactly one step of
      delay on every edge, and evaluation order does not affect the result.
      The rationale is at Brain.cs:39-47 ("a signal crosses exactly one node
      per step").
    - Drive extraction loop afterwards (:271-285): for each part with
      _dofStart >= 0, drive[start+d] = Clamp(_previous[offset+d]) for
      d < dofCount, and 0 where the part has fewer neurons than DoF (:283).
      So NEURON d OF A PART DRIVES DOF d OF ITS JOINT — the mapping is defined
      here, not in the genome (Brain.cs:48-56).

4.4 INPUT KINDS (Brain.cs:417-454; enum at NeuronInput.cs:13-32)

      Sensor     -> sensors.Read(part, Channel, Index) * Weight   (§3)

      ChildNode  -> FromGroup(_firstChild[part], Index), 0 at a leaf

4.9 SIZES AND BOUNDS — the important one for a GPU port
    - Neurons per part: founders draw MinNeuronsPerNode..MaxNeuronsPerNode =
      1..3 (GenomeFactory.cs:84-85, :734). MUTATION HAS NO CAP: a node gains a
      neuron with probability AddNeuronChance = 0.05 and loses one with
      RemoveNeuronChance = 0.04 per mutation (MutationRates.cs:115,:117;
      Mutator.cs:582-599). Neuron count per node is therefore an unbounded
      random walk with a slight upward drift. N has no static bound.
    - Inputs per neuron: set at founding to the op's arity, 0..3
      (GenomeFactory.cs:752-770). Mutation only *rewires* inputs, never adds or
      removes them (Mutator.cs:618-635), and an op mutation does not resize the
      array — so inputs/neuron <= 3 for any lineage descended from a founder,
      but a neuron may hold fewer inputs than its current op's arity (the
      evaluator reads the missing ones as 0, Brain.cs:340-342).
    - Edges per node at founding: MaxEdgesPerNode = 2 (GenomeFactory.cs:16,
      :783). Mutation may exceed it (options remark, GenomeFactory.cs:60-65).
    - Parts/joints: MaxParts = 16, MaxDepth = 8 (DevelopmentLimits.cs:10,:14).
    - DoF per joint: 0..3 (JointType.cs:24-37).

4.10 CADENCE — every physics step. The brain's clock advances by dt each call
     (:250), so the oscillators are in simulated time.

9.4 DATA-DEPENDENT CONTROL FLOW
    - Inward walks i = L-1 down to 1 (:65). REQUIRES Parent[i] < i, which
      Creature.cs:52 guarantees ("Always less than the child's index"), so the
      sequential walk is a valid topological order with no tree traversal.
    - `if (n > 0) ... else` (:77 / :163) — a fixed joint takes a short path.
    - Inner k x k loops over n (0..3): four separate nested loops
      (:82-89, :93-113, :128-145, :154-161).
    - The D matrix is assembled into six named scalars by an if/else-if chain
      on (j, k) (:106-111) — an unrolled 3x3 upper triangle.
    - `if (w == 0) continue;` inside the I^a update (:136).

§F. THE SHAPE OF A LINK, AND THE JOINTS
================================================================================
F.1 LINK GEOMETRY
  A link's frame is the developed part's own frame: origin at the part's
  centre, so the centre of mass is the origin and the inertia tensor is
  DIAGONAL — which is why the solver carries 3 numbers per link, not 6
  (Creature.cs:19-25).
  Shapes are resolved from PhenotypePart.ShapeId through a PartShapeRegistry
  (Creature.cs:272, Growth.cs:191). The three standard shapes
  (src/Evosim.Core/Shapes/StandardShapes.cs):
    Box      — half-extents (hx, hy, hz); inertia k*(hy²+hz²) etc.,
               k = mass/3 (Creature.cs:558-568)
    Sphere   — radius = SphereShape.Radius(halfExtents); I = 0.4*m*r²
               (Creature.cs:528-533)
    Capsule  — cylinder + two hemispheres about the local Y axis;
               r = CapsuleShape.Radius(h), s = CapsuleShape.HalfSpan(h);
               the along/across split is written out at Creature.cs:535-556
    Unknown  — falls back to the box tensor (Creature.cs:558; "counted nowhere
               — no run in the record carries one")
  Half-extents are Float3 (PhenotypePart.cs:28) — FLOAT, widened at use.
  Mass: plain = max(MinimumLinkMass, volume * TissueDensity); effective =
  plain + AddedMassCoefficient * Density * volume; the tensor is scaled by
  effective/plain (Growth.cs:201-211).

F.2 JOINT TYPES AND DoF  (src/Evosim.Core/Genome/JointType.cs:7-38)
    Fixed 0 | Hinge 1 | Twist 1 | HingeTwist 2 | TwistHinge 2 |
    Universal 2 | Spherical 3
  The joint's rotation is Rx(q0) Ry(q1) Rz(q2) truncated to the DoF count
  (Kinematics.cs:18-25, :146-162) — EXCEPT a 3-DoF joint, which carries a
  QUATERNION (BallRotation[4L]) because the Euler composition is singular at
  q1 = ±π/2 and round 42 threw five genomes into it (Creature.cs:155-178).
  A ball joint's velocity coordinates ARE the relative angular velocity in the
  child's joint frame, so its motion subspace is the identity and never
  degenerates (Kinematics.cs:177-179).
  Joint frames: JointFrame is the child's (anchorRotation), RestFrame the
  parent's; a hinge's frame is Euler(0, π/2, 0), everything else identity
  (Creature.cs:27-32, :507-510).
  Joint limits are penalty SPRINGS here, not hard constraints — stiffness
  I·ω² per DoF against the two-body reduced inertia about the axis, ω =
  JointLimitOmegaTimesStep(1.5)/dt, carried implicitly on D's diagonal
  (DynamicsWorld.cs:190-203, Creature.cs:99-127, Growth.cs:261-296,
  SolverConfig.cs:105-139).
